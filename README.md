# 什么值得买 (SMZDM) 好价监控推送系统

基于 GitHub Actions 的单次扫描脚本。它抓取什么值得买好价列表，先用互动数据筛出候选，再通过评论用户等级、评论用户集中度、互动异常、相似商品去重和降价判断，尽量减少水军爆料和重复推送。

## 当前逻辑

### 1. 数据源

- 主列表接口：`https://api.smzdm.com/v1/list?limit=20&offset=N`
- 只扫描 `faxian`、`youhui` 两类频道。
- 每次最多扫描过去 6 小时内的数据。
- 脚本是单次运行模式：扫描 -> 筛选 -> 推送 -> 退出，没有常驻循环。

### 2. 第一阶段：互动评分初筛

综合评分公式：

```text
综合评分 = 评论数 * 3 + 收藏数 * 2 + 值票数 * 1
```

当前有三条放行路径：

| 路径 | 门槛 | 用途 |
| --- | --- | --- |
| 均衡热度 | 评论+收藏+值 >= 15，综合评分 >= 45，好评率 >= 70% | 正常热门商品 |
| 高讨论 | 评论 >= 8，互动 >= 20，综合评分 >= 70，好评率 >= 70% | 讨论较多且好评率不低的商品 |
| 早期好价 | 值 >= 4，评论 >= 3，互动 >= 12，综合评分 >= 25，好评率 >= 90% | 刚开始发酵且好评率很高的潜在好价 |

基础要求：值票至少 2 或评论至少 2。售罄、过期、已结束会直接过滤。

脚本不再做标题关键词和分类/tag 硬过滤。流量卡、红包、券、运营商、金融等内容如果互动质量达标，会继续进入后续判断；这类内容建议在 WXPusher 侧用关键词屏蔽。

### 3. 评论等级和评论集中度检测

对初筛候选调用移动端详情模块：

```text
https://haojia.m.smzdm.com/detail_modul/user_related_modul?article_id={article_id}
```

从返回 JSON 中读取评论用户的 `vip_level` 和用户信息。这个模块不是完整评论分页，通常只返回热评/相关评论样本；脚本会记录模块声明的评论总量、原始样本数、作者评论数和非作者样本数。

- Lv5 及以下视为低等级账号。
- Lv6 及以上视为更可信账号。
- 低等级评论用户占比超过 35% 时过滤。
- 可取评论样本达到 4 条后，会检查评论是否集中在少数用户：
  - 独立用户少于 3 个时过滤。
  - 单个用户评论占比超过 50% 时过滤。
- 如果成熟商品只能取到 2 条评论样本，但两条都是 Lv6+ 且来自不同用户，同时商品好评率 >= 85%，并且评论数 >= 10 或综合评分 >= 80，则允许少样本通过。
- 如果模块声明评论总量 >= 50，但热评模块只给出少量非作者样本，脚本不会把这几个热评样本当作完整评论区代表来直接判水军；成熟商品在好评率 >= 95%、评论 >= 15、综合评分 >= 50、非作者样本 >= 2、低等级样本不超过 1 个且至少有 1 个 Lv6+ 时，可走“大评论区少样本通过”。
- 大评论区非作者样本少于 5 条且未满足放行条件时，会暂缓复评，而不是按热评样本的低等级比例直接过滤。
- 早期好价不走少样本通过，必须等到评论等级可确认或后续数据继续发酵。

### 4. 评论等级不可用时的暂缓复评

评论接口可能返回样本不足、触发外部熔断，或本轮评论校验预算耗尽。脚本不会把这类商品直接写入已推送历史，而是按规则暂缓，下轮扫描继续根据最新互动数据复评。

- 本轮评论校验预算是动态计算的：常规情况下校验全部可校验候选，最高 80 条，避免预算不足造成额外半小时级延迟。
- 早期好价：评论等级不可用时默认暂缓，避免 `🆕新` 商品靠少量水军评论直接推送。
- 均衡热度/高讨论：样本不足或外部不可用时先暂缓；同一商品连续暂缓达到配置次数后，只有好评率 >= 85%、评论 >= 15、综合评分 >= 90 的成熟高信号商品才可兜底放行。
- 评论预算不足：普通商品暂缓；只有综合评分 >= 120 且评论 >= 20 的强信号商品才允许预算不足时放行。
- 暂缓记录保存在 SQLite 的 `pending_reviews` 表，默认保留 2 天。

### 5. 互动异常兜底

当总投票数达到 30 后，脚本会检查两个异常信号：

- 值/不值比例超过 20。
- 评论数/值票数低于 0.2。

同时命中 2 个异常信号才会判定为水军嫌疑并过滤。

### 6. 去重和降价再推送

- 只有推送成功的商品才写入 `history`。
- 同一文章 ID 已推送过会跳过。
- 相似标题会生成商品指纹，3 天内默认只推一次。
- 如果同指纹商品价格比历史推送低至少 5 元，或降幅至少 5%，允许再次推送，并在推送内容里标记降价信息。
- 未推送、暂缓或推送失败的商品不会写入历史，下次扫描仍可重新评估。

### 7. 京东商品处理

京东自营强校验当前默认关闭。原因是 GitHub Actions 访问京东或跳转页时经常拿不到稳定的店铺/自营字段，强行过滤会误伤好价。

现在京东商品和其他平台一样，统一走互动评分、评论等级、评论集中度、互动异常和去重逻辑。

### 8. 反爬和稳定性

- 外部详情/评论请求有随机延迟。
- 如果遇到 `202/403/429`、验证码、`probe.js`、访问频繁等标记，本轮会熔断外部校验。
- 熔断后不再继续请求详情/评论接口，降低触发反爬的风险。

## 运行

```bash
pip install -r requirements.txt
WXPUSHER_APP_TOKEN=xxx WXPUSHER_UID=xxx python3 smzdm.py
```

可选环境变量：

- `WXPUSHER_APP_TOKEN`：WXPusher app token。
- `WXPUSHER_UID`：接收推送的 UID。
- `SMZDM_DB_PATH`：SQLite 数据库路径，默认 `smzdm.db`。

## GitHub Actions

`.github/workflows/smzdm.yml` 当前配置：

- GitHub schedule：每 30 分钟运行一次。
- 支持 `workflow_dispatch` 手动触发。
- 支持 `repository_dispatch`，可由 cron-job.org 请求 GitHub API 触发。
- SQLite 数据库通过 `actions/cache` 恢复和保存。
- 使用 `concurrency: smzdm-scan` 避免同仓库扫描任务并发执行。

注意：`actions/cache` 不是严格的可变数据库存储。如果多个运行非常接近，仍可能恢复到较旧缓存，导致短时间重复推送。长期更稳的方案是把状态保存到专门的 state 分支、artifact 或外部 KV/数据库。

## 推送内容

WXPusher 使用 HTML 内容，包含：

- 热度标记：`🔥爆`、`👍热`、`🆕新`
- 平台、标题、价格、发布时间
- 好评率、综合评分、值/不值/评论/收藏
- 评论等级和评论用户集中度统计
- 降价再推送说明
- SMZDM 详情链接

## 文件结构

- `smzdm.py`：主脚本。
- `requirements.txt`：运行依赖，目前只有 `requests`。
- `.github/workflows/smzdm.yml`：GitHub Actions 工作流。
- `smzdm.db`：运行时 SQLite 数据库，本地和 Actions 缓存使用。
