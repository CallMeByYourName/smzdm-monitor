# 评论检测与公开 API 调研（2026-10-11）

本轮落实上次建议的等级证据门槛和关键词过滤冷却，并修复评论解析边界、增加评论异常观察。六条互动路径、综合分权重、增长门槛和外部每 15 分钟触发保持不变。新异常指标只记录诊断，不声称已经识别水军，也不直接拒绝商品。

## 已实施的调整

| 调整 | 当前行为 | 目的 |
| --- | --- | --- |
| 等级证据 | 模块具代表性，且非作者已知等级至少 6 条、覆盖非作者样本至少 80%，才允许低等级比例超过 35% 单独否决 | 避免 3–4 条等级或 `1/1` 有效等级决定整篇文章 |
| 集中度 | 代表性模块的至少 4 条非作者样本先执行集中度检查，再处理少样本成熟例外 | 修复作者占多数时，4 条仅来自两人的评论被提前放行的旧边界；2 条成熟候选例外保留 |
| 关键词冷却 | 唯一目标 UID 明确返回用户关键词过滤才触发，同一接收人及文章冷却 45 分钟 | 降低重复请求；独立状态不冒充成功历史，到期重新评估 |
| 运行统计 | 用户关键词拒绝单独 INFO/计数；其他发送失败、未知超时分别记录 | 用户过滤结果不再伪装成运行错误 |
| 评论解析 | 缺 `vip_level` 的真实评论保留为未知等级；只用稳定用户 ID，昵称不作账号身份 | 避免丢样本或把同昵称的不同人合并 |
| 评论来源 | 只读本帖 `hot_comments_b.rows` 和 `child_list`，按评论 ID 去重并排除作者 | 不把镜像、父评论引用和其他模块当新增发言 |
| 空数据降级 | `data`、`comments` 或 `hot_comments_b` 为 null、数组等非预期形状时返回空样本 | 保留正常扫描，避免异常保护外的链式 `.get()` 中止整轮 |
| 异常观察 | 重复长正文与同组短时聚集记录数量、覆盖率、时间上界及文本哈希 | 复用既有请求，不记录正文/评论者 ID，不新增硬拒绝 |
| 旧互动比例 | 原“值多、不值少、评论少”改为互动异常诊断 | 比例异常不足以证明账号真伪；增长停滞过滤仍保留 |
| 手动诊断 | 在查询前迁移旧 SQLite 缓存表结构，并按当前接收人判断冷却 | 新表上线后，带 `debug_article_id` 的首次运行也可兼容旧缓存 |

等级、低/高比例和集中度是样本特征，不是虚假账号或真实购买的身份认证。现有等级政策仍保留，但证据不足会明确标记为跳过，不能写成“等级验证通过”。

## 匿名接口实测

2026-10-11 本机共读取一次主列表、四个评论模块、一次网页和一次公开用户资料。每次使用严格超时；网页遇验证码后停止该分支。没有向 SMZDM 发布评论、签到或删除，也没有读取私有账号数据。本机一次成功不等于 GitHub runner 长期稳定可用。

### 主列表

`GET https://api.smzdm.com/v1/list?limit=100&offset=1000` 返回 HTTP 200、`error_code=0`、`data.rows` 100 条。

除已有互动和价格字段，实际还包含 `article_brand`、`article_brand_id`、`article_category`、`article_mall_id`、`article_tag_arr` 和 `real_price_title`。`tongji_hudong` 在该响应中是 `评论_N,收藏_N,值_N,不值_N,...` 字符串，不能按字典猜测解析。当前程序沿用现有正确解析。

这些品牌/类目字段可帮助将来做偏好排序，不能直接证明同类质量；本轮未将它们变成全局屏蔽规则，也未额外逐个查询商品价格。

### 评论模块

`GET https://haojia.m.smzdm.com/detail_modul/user_related_modul?article_id=...` 四次均正常 JSON。路径是 `data.comments.hot_comments_b`。

| 文章 ID | 模块声明评论 | 实际去重返回 | 排除作者 | 非作者 |
| --- | ---: | ---: | ---: | ---: |
| 183763935 洁柔抽纸 | 5 | 4 | 4 | 0 |
| 183763922 班尼路 T 恤 | 5 | 3 | 3 | 0 |
| 183763321 五粮液白酒 | 5 | 5 | 5 | 0 |
| 183743621 极空间 NAS | 6 | 5 | 2 | 3 |

实际字段：

```text
hot_comments_b: rows, total, total_root, author_id, author_smzdm_id,
                aigc_comment_rows, aigc_children_comment_rows
评论行: comment_id, content, creation_date, user_smzdm_id, display_name,
        display_author, vip_level, root_id, child_list, child_total,
        comment_parent_id, is_buy, up_num, down_num, author_role
```

`total` 是整数；`total_root` 在这批响应可能为空字符串。`creation_date` 实测是“8分钟前”“12小时前”等相对文本。`content` 可能包含话题 HTML。NAS 三条非作者等级是 4、4、3，正文均短，时间为 12/12/11 小时前；没有足量正文或精细时间证明协作。

`aigc_comment_rows` 与正常行重复同一评论 ID，字段名不能用来证明评论由 AI 生成。`comment_parent_id` 还可能是含 ID 和绝对时间的引用字典，不是新评论。本轮解析限定实际行和子评论，未知等级仍计入返回样本。

前三个新帖的所有返回评论来自作者。列表“评论 5 条”因此不能理解成 5 个独立买家，现有作者排除必须保留。

### 完整分页与用户资料

- 一次 `GET https://www.smzdm.com/p/183743621/` 返回腾讯验证码壳，无文章评论 DOM。未找到可直接加入生产且已证明稳定的匿名完整评论 JSON 分页；不猜 URL、反复重试或加入验证码绕过。
- 一次匿名读取 `POST https://api.smzdm.com/v1/users/info`，表单仅含已有评论者的公开 `user_smzdm_id`，返回 `error_code="0"`。实际有累计 `data.comments`、`data.articles`、等级/积分 `data.meta`、平台角色 `data.role.is_media/is_official/is_merchant`。没有注册时间、完整评论历史或购买证明。
- [平台评论查询文档](https://openapi.zhidemai.com/pages/price/3.%E8%AF%84%E8%AE%BA%E6%9F%A5%E8%AF%A2API.html)要求 `Access_Token`、`App_Key`，输入商品 `Url` 和时间范围，返回评论正文/时间。未证明这是爆料评论分页，也未给评论者等级/ID，不能作为当前匿名替代源。

用户资料逐个获取会增加请求、缓存和失败处理成本，当前数据收益不足，本轮未接入生产。

## 异常观察具体边界

1. 先按评论 ID 去重并排除作者；缺稳定 ID 的评论保留在样本中，但不参与跨账号正文重复计数。
2. 非作者样本至少 6 条，规范化后正文至少 24 字符，同一正文涉及至少 4 个稳定账号、占全部非作者样本至少 60%，记录重复长文本。
3. 去 HTML、显式引用块、空白，规范化全宽字符和大小写，保留数字与标点含义。不将“好价”“已买”“谢谢”等短句判为模板。
4. 仅当重复组每条都有可解释时间，整个时间区间上界不超过 180 秒，追加短时聚集信号。“N 分钟前”保留一分钟不确定区间，“N 小时前”保留一小时区间；未知、未来或荒谬年龄不填成当前时间。
5. 覆盖不足仍可记录“样本中有异常”，但不能代表完整评论区。日志只存数量、时间上界和文本哈希；详情只在购买链接后的诊断区提示。
6. 两个指标命中也仍是观察模式。重复报价、活动文案、用户引用、热评偏置可能造成误报，缺少真实标注前不承诺准确率或自动清除水军。

这些初始数字是保守的诊断参数，不是统计证明的最佳阈值。跨帖同群体检测需要更多完整行为历史和同 SKU 重复爆料保护，当前数据不足，未加入。

## 下一步优化优先级

| 优先级 | 方向 | 本轮结论 |
| --- | --- | --- |
| 高 | 同 SKU、规格、数量、会员/优惠/返还条件的可比价格观察 | 比再次调高热度分更接近“质量合适时出现好价”；需独立价格观察表和严格语义，当前推送最低价有选择偏差，不是市场史低 |
| 高 | 明确品牌/型号及品类偏好用于排序 | 可用现有品牌/类目字段；不能凭品牌认证质量，也不能从已推商品推断用户兴趣 |
| 中 | 收集异常观察的具体文章、复查误报与漏报 | 有稳定样本和用户判断后，再决定是否启用某种组合拒绝；推送数量减少不是成功指标 |
| 中 | 更可靠的持久状态 | Actions cache 不是事务性可变数据库；需要独立存储才能进一步改善临近运行/重试的旧状态恢复风险 |
| 暂缓 | 完整评论翻页、逐用户角色筛选、浏览器抓 JD/评论 | 数据价值和 runner 可用性未得到证明；不增加无界请求或把接口失败当商品差 |
| 保留 | 每 15 分钟扫描 | 早期候选需要复观测，最近运行约 4 分钟；本轮没有新时延或限流证据支持降频/加频 |
