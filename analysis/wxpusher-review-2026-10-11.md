# WXPusher 推送体验评估（2026-10-11）

结论：优先补独立原文链接、压缩摘要中的条件用词、增加复制按钮。最明显的问题是原文入口缺失及短通知里商品名可能出现太晚，继续堆 HTML 信息不能改变客户端列表布局。初次评估仅调研和回放；用户随后授权实施，实施结果见文末。

## 优先改进

### 1. 补发送 JSON 的 url 字段

现在只在 HTML 正文中放链接，没有发送独立 `url`。建议把已有 `data.link` 的 SMZDM 原文链接填入该字段，保留正文购买入口。这不需要额外抓取。

iOS 源码中，正文行点击打开消息详情，sourceUrl 非空时另显示原文链接图标。用户还可在“我的 → 通用 → 通知点击设置”选择原文链接；这是接收手机自己的设置，服务端不能强制开启，列表点文字仍进入详情。

优先链接到原始爆料，让优惠券、会员、凑单和返还说明有上下文。京东/淘宝 Scheme 需逐平台、逐设备实测，不能根据 SKU 猜测后作为默认入口，也不能承诺一定绕过网页或平台广告。

实现时 JSON 使用原始、经过校验的 HTTP(S) 地址，不能把 HTML 中的 `&amp;` 转义串直接当 API URL；不可用、过长或非允许协议时省略，不影响正常发送。

### 2. 缩短条件措辞，让价格之后尽快出现商品名

独立 summary 已经正确使用，但接口允许 100 字不等于手机能完整显示。部分通知场景约只展示 20 字；iOS 列表固定两行并截断。建议继续遵守“价格 → 购买条件 → 商品 → 事实理由”，仅压缩条件：

```text
PLUS会员 → PLUS
需买2件 → 需2件
用券 → 券
```

保留会员、数量、国补、返还等实质条件，不把多件价格写成单件到手价，不删除“折算”“起”“价差未核实”。型号规格仍由原标题提供，不能用人工缩写掩盖差异。

示例（只示意格式，未上线）：

```text
当前：26.81元｜需买2件/用券｜得宝 抽纸4层 90抽*18包｜16值、8评；价差未核实
建议：26.81元｜需2件/券｜得宝 抽纸4层 90抽*18包｜16值/8评；价差未核实
```

268 条历史记录按当前代码回放：摘要中位数 46 字、最长 61 字，9 条商品名从第 21 字或之后才开始。只压缩上述条件后，这类情况降为 2 条。字符位置不等于屏幕宽度，这不是实际通知点击率或 UI 改善的测量；具体还需手机确认。

### 3. HTML 增加复制商品名称/原文链接按钮

官方支持 `<copy data-clipboard-text="...">`，适合复制完整商品名称去商城搜索，或者分享原文链接。建议放在购买入口旁，保留普通超链接作入口，正文无需换成 Markdown。

复制属性必须转义；只能复制已有真实数据，不能从爆料正文猜口令、券码或 SKU。普通浏览器预览不会自动实现 WXPusher 的复制行为，需要在实际客户端确认。

## 较低优先级的保护

| 项目 | 当前证据 | 建议 |
| --- | --- | --- |
| 发送节流 | 39 轮旧日志中的可见发送尝试，最大每 10 秒 4 次、最短相邻约 0.67 秒；未发现此窗口限流证据 | 可用单调时钟保证最短发送间隔，覆盖没有评论请求的快速候选；保留 POST 超时不立即重试 |
| 正文长度预检 | 历史回放 HTML 最大 1613 个 UTF-8 字节，距限制很远 | 加字符/字节预检可以让异常报价失败更清楚，但当前不是主要体验问题；服务端转换长度仍不能完全在本地保证 |
| 商品图片 | 主列表已有图片字段，但当前解析未保留 | 可在详情使用；iOS 原生列表仍是两行摘要，不会因为 HTML 放图就变成图片卡片。暂不因此新增抓取 |
| 主题订阅 | 当前单 UID 且希望广泛发现 | 以后多用户需要独立偏好时再考虑；现在没有必要迁移 Topic 或 SPT |
| 合并摘要推送 | 能减少通知数，却降低实时性和逐商品入口便利 | 用户目前希望继续广泛发现，暂不将全部好价合并成定时汇总 |

## 发送状态查询：实测已停用

文档和 OpenAPI 仍列出 `GET /api/send/query/status`。本轮仅用已有发送记录 `2505226494` 做了一次匿名只读查询，HTTP 200，业务码 1001，success=false，提示“发送状态查询已停用”，要求停止调用/轮询。提示也明确不代表消息发送失败。

因此不建议新增状态轮询，也不能把这次状态查询失败拿去删除成功历史或重发消息。继续按唯一目标 UID 的接受结果记账，并保留“任务已受理，终端到达未确认”的语义。

## 边界与建议范围

本次优先方案仅是原文入口、短摘要和复制功能；不改变选品、评论策略、价格对照语义或 15 分钟扫描时机。HTML 详情已有价格和条件在前、诊断在后，无需再大改结构。

短摘要不能解决用户对商品本身不感兴趣的问题。更接近购买价值的改进仍是明确偏好排序和同规格、同购买条件的价格观察；WXPusher 提供的是呈现与触达能力，不能替脚本验证商品品质或市场好价。

临时证据保存在 `/tmp/smzdm-wxpusher-review-20261011/`：官方文档、OpenAPI、iOS 源码、状态查询原始响应。没有发送 POST、删除消息、修改用户设置或增加后台轮询。

## 授权后的实施

- 发送 JSON 增加有效的独立 HTTP(S) 原文链接，最多 1000 字符。缺失、非法协议、凭据、非法端口或控制字符等链接省略，正文仍可发送；JSON 的查询参数保留原始 `&`。
- 摘要条件使用 `PLUS`、`需N件`、`券`，完整条件留在详情。摘要预留商品和未核价提示空间，极端复杂报价不会将“价差未核实”截掉；异常超长数量提示“数量见原文”。
- 详情购买入口旁增加官方 `<copy>` 标签；复制完整清理后商品名及可用原文链接，HTML 属性转义，保留型号规格。
- 六条筛选路径、评论策略、触发时机及成功历史规则未改变；没有新增抓取或发送状态轮询，没有更改手机通知点击设置。
- 新增/调整回归检查 URL 原始参数与省略边界、复制属性防注入及完整名称、购买条件压缩、极端摘要长度和不新增状态查询。
- 103 项 Python 3.11 单元测试通过。268 条历史记录回放：摘要中位数 45 字、最长 59 字，商品名从第 21 字或之后才开始的情况为 2 条；HTML 最大 2123 个 UTF-8 字节。历史回放不验证手机终端到达或原生复制功能。
- 新增[本地预览](notification-preview-2026-10-11.html)，模拟两行摘要与原文入口，普通浏览器用演示代码实现复制。历史 CSV 的 `url` 是 Actions 证据页，预览按已有文章 ID 构造 SMZDM 原文地址；生产始终直接复用实际 `article_url`。
- 浏览器在 390×844 宽度下检查无横向溢出，点击复制商品名显示“已复制”；临时视口随后恢复。复制测试属于本地浏览器演示，原生 WXPusher 手机行为仍需客户端确认。
